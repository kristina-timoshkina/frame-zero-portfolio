## Производительность

Главная 3D-сцена остаётся центральным художественным элементом, но получает адаптивный режим качества:

- На смартфонах и слабых устройствах уменьшаются плотность частиц, внутреннее разрешение и частота перерисовки.
- Вне первого экрана постоянная отрисовка прекращается после завершения затухания сцены; остаётся статичный кадр, если он нужен композиции.
- На главном экране анимация ограничивается разумной частотой кадров, чтобы не конкурировать со скроллом и вводом.
- Bloom и multisampling не отключаются безусловно: для слабого профиля применяется облегчённая конфигурация, для остальных устройств внешний вид сохраняется.
- Превью изображений переводятся в современные форматы только там, где есть безопасная кроссбраузерная подстановка или неизменённый JPEG-fallback.

Целевой результат: ощутимо меньшая нагрузка на CPU/GPU при сохранении визуального впечатления. Ранее оптимизированная монтажная не должна снова начать заранее загружать MP4.

## Доступность

- Скрытый полноэкранный просмотр видео не должен оставлять кнопку «Закрыть» в таб-порядке; при закрытии применяется `inert` вместе с `aria-hidden`.
- Доступные имена интерактивных элементов включают их видимый текст: «Монтажная», «PLAY», «Завершить монтаж».
- Маленькие кнопки управления звуком получают удобную сенсорную область без изменения видимого оформления.
- Контактные ссылки имеют осмысленные доступные имена и заметный фокус.

## Медиаресурсы и репозиторий

После проверки ссылок и контрольных сумм удаляются только точные неиспользуемые дубликаты видео `.m4v`, если у них есть функционально равнозначный `.mp4`. Никакие исходники и единственные медиафайлы не удаляются. Удаление должно уменьшить вес репозитория и публикации, но не влиять на доступность сайта для посетителей.

## Проверка

После реализации:

1. `npm run build` завершается успешно.
2. В браузере проверяются desktop и mobile: главная, вход в монтажную, четыре зала, трейлер, полный фильм, возврат в FRAME ZERO, контакты.
3. Lighthouse для production preview проверяет улучшение главной страницы и отсутствие регрессии у монтажной.
4. Проверяются нулевая ошибка в консоли, отсутствие ранних запросов к MP4 в монтажной и работа с клавиатуры.
5. Изменения отправляются в GitHub отдельным pull request; после слияния проверяется GitHub Pages.
