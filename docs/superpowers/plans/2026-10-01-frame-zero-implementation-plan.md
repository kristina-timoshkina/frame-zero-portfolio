# FRAME ZERO — план реализации

Дата: 1 октября 2026 года  
Основание: `docs/superpowers/specs/2026-09-30-frame-zero-landing-design.md`  
Статус: готов к выполнению

## Цель

Собрать, проверить и опубликовать на GitHub Pages одностраничный русскоязычный интерактивный лендинг FRAME ZERO. Страница показывает вклад Евгения Тимошкина в реальные и учебные видеоработы, отделяет авторские эффекты внутри роликов от интерактивной подачи сайта и остаётся быстрой, управляемой и доступной.

## Техническое решение

- Vite и vanilla JavaScript без тяжёлого UI-фреймворка.
- Three.js только для постоянного 3D-слоя, ядра, частиц и нескольких переходов.
- GSAP ScrollTrigger для привязки анимаций к естественной прокрутке без перехвата колеса мыши.
- Нативные HTML5 `video` и `audio` с единым контроллером активности.
- MP4 H.264 720p/1080p и статичные постеры; исходники не изменяются.
- Относительная база Vite `./`, чтобы одна сборка работала как на GitHub Pages, так и из ZIP-архива.

## Этап 1. Защита репозитория и каркас

Файлы:

- создать `.gitignore`;
- создать `package.json`, `vite.config.js`, `index.html`;
- создать пустые каталоги `src`, `public/media`, `scripts`;
- исключить `.DS_Store`, `node_modules`, `dist`, временные файлы и папку исходных видео из Git.

Действия:

1. Зафиксировать Vite, Three.js и GSAP в зависимостях.
2. Настроить `base: './'` и выход в `dist`.
3. Добавить команды `dev`, `build`, `preview` и `check`.
4. Убедиться, что документация остаётся в Git, а тяжёлые исходники — нет.

Проверка:

- `npm install`;
- `npm run build`;
- `git status --short` не показывает `node_modules`, `dist` и исходные видео.

## Этап 2. Инвентаризация и подготовка медиа

Файлы:

- создать `docs/media-selection.md`;
- создать `scripts/prepare-media.sh`;
- создать производные файлы только в `public/media/clips` и `public/media/posters`.

Действия:

1. Просмотреть каждый выбранный ролик и записать точные таймкоды сильных фрагментов.
2. Для пяти главных сцен выбрать короткие клипы ориентировочно по 4–10 секунд.
3. Для компактных подборок подготовить клипы по 2–5 секунд.
4. Использовать `/usr/bin/avconvert` с `Preset1280x720` или `Preset1920x1080`, `--start`, `--duration` и фильтрацией метаданных.
5. Подготовить постеры через кадр из клипа или подходящее присланное изображение; оптимизировать через `sips`.
6. Не удалять, не переименовывать и не перезаписывать файлы в `видео лендинг`.
7. Не переносить в `public` дубликат `Разрушение здания 2.mp4`.
8. До подтверждения происхождения использовать нейтральный статус «Работа из портфолио».

Проверка:

- производные клипы открываются в Safari и Chrome;
- автоматические клипы беззвучны и имеют постеры;
- первый экран вместе с кодом и графикой ориентируется на объём до 5 МБ;
- полное последовательное прохождение ориентируется на 60–80 МБ;
- ни один исходный файл не изменён.

## Этап 3. Данные и семантический каркас страницы

Файлы:

- `src/app/projects.js`;
- `src/app/AppShell.js`;
- `src/components/CaseSection.js`;
- `src/components/MediaFrame.js`;
- `src/main.js`.

Действия:

1. Создать единый манифест проектов: идентификатор, заголовок, статус, вклад Евгения, задача, результат, технические детали, клип, постер и цветовой акцент.
2. Собрать структуру: hero → погружение → портал → Buzz → футбол → история и ритм → VFX Lab → блогеры и эксперты → Tim Cut → финал.
3. Выводить вклад Евгения отдельной компактной подписью внутри кинорамки.
4. Добавить раскрываемый блок «Как это сделано».
5. Добавить понятный контент даже при отключённом JavaScript/3D: заголовки, постеры и описания остаются читаемыми.

Проверка:

- на первом экране сразу понятны название и специализация;
- все разделы доступны по якорям;
- ни один текст проекта не дублируется внутри визуальных компонентов;
- авторство относится только к перечисленным видам работы.

## Этап 4. Визуальная система и адаптивная сетка

Файлы:

- `src/styles/tokens.css`;
- `src/styles/base.css`;
- `src/styles/layout.css`;
- `src/styles/components.css`;
- `public/favicon.svg`;
- `public/og-frame-zero.jpg`.

Действия:

1. Реализовать полуночную палитру, ультрафиолет, ледяной голубой, пурпурный бархат и точечные тёплые акценты.
2. Создать два визуальных языка:
   - работа Евгения — чистая кинорамка, исходный цвет, подпись о вкладе;
   - FRAME ZERO — стекло, частицы, полупрозрачный свет и линии плёнки за рамкой.
3. Настроить типографику с кириллицей и локальным запасным шрифтом.
4. Собрать адаптивную сетку для 1366×768, 1440×900, 1920×1080 и узких экранов.
5. Добавить заголовок вкладки, favicon и метаданные превью.

Проверка:

- текст не перекрывается видео;
- контраст соответствует минимуму WCAG AA для основного текста;
- нет горизонтальной прокрутки;
- Tim Cut сохраняет оригинальные синий и жёлтый цвета внутри отдельной стеклянной рамки.

## Этап 5. Постоянный 3D-слой FRAME ZERO

Файл:

- `src/three/SceneCanvas.js`.

Действия:

1. Создать одну сцену Three.js, один renderer и одну камеру на всю страницу.
2. Собрать жидкое ядро из геометрии с мягкой деформацией, прозрачным материалом и внутренним светом.
3. Добавить ограниченное количество частиц и реакцию на курсор с плавным затуханием.
4. Не создавать отдельные WebGL-контексты для каждого раздела.
5. Останавливать рендер при скрытой вкладке и снижать pixel ratio на слабом устройстве.
6. Реализовать статичный CSS-fallback при отсутствии WebGL или `prefers-reduced-motion`.

Проверка:

- ядро видно одновременно с текстом первого экрана;
- кнопка «Смотреть проекты» доступна с первой секунды;
- нет длительной заставки;
- после скрытия вкладки нагрузка снижается;
- fallback сохраняет композицию без WebGL.

## Этап 6. Естественный скролл и киноплёнка

Файлы:

- `src/controllers/ScrollDirector.js`;
- `src/components/FilmstripNav.js`;
- `src/styles/motion.css`.

Действия:

1. Создать единую временную линию ScrollTrigger без блокировки колеса мыши.
2. Связать состояние активной сцены с киноплёнкой справа.
3. Показывать предыдущий, текущий и следующий кадры; остальные не раскрывать.
4. Поддержать клик, клавиатуру, видимый фокус и мягкий переход к якорю.
5. На узком экране заменить плёнку компактным индикатором.
6. При `prefers-reduced-motion` убрать пролёты, тряску и motion blur.

Проверка:

- пользователь может свободно пролистать любую сцену;
- киноплёнка не закрывает текст на 1366×768;
- активный кадр соответствует видимому разделу;
- навигация работает клавиатурой.

## Этап 7. Пять основных сцен

Файлы:

- `src/components/CaseSection.js`;
- `src/controllers/ScrollDirector.js`;
- `src/three/SceneCanvas.js`;
- `src/styles/components.css`;

Действия:

1. Portal: сначала показать подписанный фрагмент работы, затем расширить свет и частицы за кинорамку и выполнить переход.
2. Buzz: показать вертикальное видео, задачу, вклад и результат; карту и батарею оставить лёгкими интерфейсными акцентами.
3. Футбол: собрать монтажную линию из нескольких кадров и вывести «250 ГБ · 6 матчей · одна история».
4. История и ритм: объединить два трейлера и ZADE без одновременного проигрывания роликов.
5. VFX Lab: показать автомобиль, разрушение, Magic Mask и цветокоррекцию; три дополнительных эксперимента поместить в короткую ленту.
6. Во всех breakout-сценах соблюдать последовательность: контекст → фрагмент → продолжение интерфейсом → пояснение → выход.

Проверка:

- эффект из ролика сначала читается внутри подписанного кадра;
- веб-эффект существует только снаружи рамки;
- вклад Евгения сформулирован точно;
- одновременно играет не более одного основного видео;
- тряска короткая и применяется только один раз, если второй удар не оправдан тестированием.

- ошибочный медиафайл заменяется постером и текстом;
- одновременно не звучат несколько роликов.

## Этап 10. Производительность и доступность

Файлы:

- все файлы `src`;
- итоговые `public/media`.

Действия:

1. Lazy-load медиа ниже первого экрана и preload только ближайшую сцену.
2. Замораживать невидимые анимации и тяжёлые расчёты.
3. Ограничить количество частиц и pixel ratio.
4. Проверить фокус, клавиатуру, контраст, `aria`-подписи и reduced motion.
5. Убедиться, что звуковые и визуальные события дублируются текстом.
6. Проверить отсутствие абсолютных локальных путей.

Проверка:

- `npm run build` проходит без ошибок;
- консоль браузера чистая;
- страница остаётся управляемой при медленной загрузке видео;
- ошибки одного ролика не блокируют другие сцены.

## Этап 11. Финальная визуальная проверка

Среды:

- Chrome и Safari на macOS;
- 1366×768, 1440×900 и 1920×1080;
- узкий экран;
- обычное и уменьшенное движение;
- звук выключен и, при наличии, включён.

Порядок:

1. Пройти страницу от начала до конца как преподаватель.
2. Проверить, что смысл понятен за 15 секунд, а полное прохождение занимает около 2–3 минут.
3. Проверить авторство каждого кейса.
4. Проверить пять фирменных эффектов и паузы между ними.
5. Проверить киноплёнку, кнопки, паузу видео и переходы.
6. Исправить визуальные скачки, дёрганые сцены и лишние одновременные движения.

Критерий выхода: визуальная версия не содержит блокирующих ошибок и готова к пользовательским корректировкам.
